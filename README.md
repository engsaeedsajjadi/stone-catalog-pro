# Stone Catalog Pro — Enterprise Edition

پلتفرم Enterprise کاتالوگ دیجیتال، مدیریت فروش، CRM و سایت‌ساز بدون کدنویسی.

## مهم‌ترین قابلیت جدید: Site Designer

مدیر سیستم از پنل **طراحی سایت** می‌تواند بدون دسترسی به سورس‌کد این موارد را مدیریت کند:

- نام و شعار کسب‌وکار
- لوگو و تصویر Open Graph با آپلود واقعی فایل
- تلفن، ایمیل، واتساپ، آدرس، شهر، کشور و شبکه‌های اجتماعی
- رنگ‌های برند، رنگ پس‌زمینه، رنگ متن، گردی کارت‌ها و نوع دکمه
- منوی سایت و ترتیب/نمایش آیتم‌ها
- صفحه اصلی با بلوک‌های قابل افزودن، حذف، جابه‌جایی و انتشار
- Hero، متن، تصویر+متن، محصولات، دسته‌بندی‌ها، ویژگی‌ها، آمار، گالری، testimonials، CTA، تماس و فاصله
- صفحه «درباره ما» و «تماس با ما»
- فوتر
- SEO سراسری و Open Graph
- پیش‌نمایش سایت بدون ویرایش کد

هیچ محتوای تجاری نمونه در این نسخه seed نمی‌شود. تا زمانی که مدیر واقعی اطلاعات را ثبت نکند، سایت آن محتوا را نمایش نمی‌دهد.

## بلوک‌های صفحه اصلی

صفحه اصلی از فهرست بلوک‌های `pages.home.blocks` ساخته می‌شود و به‌صورت پیش‌فرض شامل
هیرو، دسته‌بندی‌ها، محصولات ویژه، جدیدترین محصولات و CTA است (همان ساختار قالب، بدون
هیچ محتوای ساختگی). هر بلوک را می‌توان افزود، حذف، جابه‌جا، غیرفعال و کامل ویرایش کرد.

| نوع بلوک | قابلیت‌های قابل ویرایش |
| --- | --- |
| `hero` | چند اسلاید (تصویر، برچسب، عنوان، زیرعنوان، متن و لینک دکمه)، ارتفاع، زمان چرخش، نمایش جستجو |
| `products` | منبع (ویژه / جدیدترین / پرفروش / صادراتی / همه)، تعداد، پس‌زمینه تیره |
| `categories` | نوع نمایش (شبکه‌ای / لیستی)، تعداد، نمایش تصویر |
| `features` | آیتم‌ها با آیکون، عنوان، توضیح + تعداد ستون |
| `stats` | آیتم‌ها با مقدار، برچسب و توضیح |
| `testimonials` | آیتم‌ها با نام، سمت، متن نظر و امتیاز |
| `gallery` | تصاویر و تعداد ستون |
| `richtext` | متن، تراز و پس‌زمینه (ساده / ملایم / تیره) |
| `image-text` | متن، تصویر، جای تصویر، متن و لینک دکمه |
| `cta` | متن، دکمه، لینک، تصویر پس‌زمینه، تراز |
| `contact` | متن معرفی، نمایش فرم (اطلاعات تماس از برند خوانده می‌شود) |
| `spacer` | ارتفاع فاصله |

بلوکی که محتوایش خالی باشد روی سایت چیزی نمایش نمی‌دهد؛ بنابراین می‌توان بلوک را
رها کرد تا بعداً تکمیل شود.

راهنمای قدم‌به‌قدم و مصورِ داشبورد (هر فیلد دقیقاً کجای سایت را تغییر می‌دهد) در
[`docs/site-designer-guide.md`](docs/site-designer-guide.md) آمده است.

## Storage واقعی

`STORAGE_PROVIDER=local` برای محیط داخلی و `STORAGE_PROVIDER=s3` برای AWS S3/Cloudflare R2 قابل استفاده است. همه تصاویر از File Picker و `multipart/form-data` وارد می‌شوند و URL خام برای تصویر محصول پذیرفته نمی‌شود.

## Webhookها

وب‌هوک‌ها را از پنل مدیریت تعریف کنید؛ ارسال واقعی توسط Worker انجام می‌شود:

```powershell
npm run worker
```

هر درخواست با هدر `x-stone-signature` (امضای HMAC-SHA256 از بدنه با کلید secret وب‌هوک)
و هدر `x-stone-event` ارسال می‌شود. رویدادهای فعلی:

| رویداد | زمان وقوع |
| --- | --- |
| `inquiry.created` | ثبت استعلام جدید |
| `contact.created` | ارسال فرم تماس |
| `order.created` | ثبت سفارش |
| `product.created` / `product.updated` / `product.deleted` | تغییرات محصولات |

ارسال با تلاش مجدد انجام می‌شود (حداکثر ۵ بار با فاصله‌ی افزایشی) و شکست وب‌هوک
هرگز باعث خطای درخواست کاربر نمی‌شود.

## سرویس‌های خارجی

Meilisearch، AI، OTP، Google OAuth، اعلان‌ها، ERP و درگاه پرداخت فقط با Credential واقعی فعال می‌شوند. در صورت تنظیم نشدن Provider، سیستم خطای «provider not configured» می‌دهد و هیچ پاسخ یا داده ساختگی تولید نمی‌کند.

## Worker

برای Job/Webhookهای پس‌زمینه:

```powershell
npm run worker
```

## Backup

`PG_DUMP_PATH` باید مسیر واقعی `pg_dump` باشد:

```powershell
npm run backup
```

خروجی به صورت فشرده (custom format) در پوشه‌ی `BACKUP_DIR` (پیش‌فرض `backups`) ذخیره می‌شود.

## امنیت

تنظیمات پیش‌فرض برای استقرار پشت یک پروکسی معتبر (Caddy/Nginx) در نظر گرفته شده است:

- تمام درخواست‌های غیر-GET باید `Origin` یا `Referer` منطبق با `Host` داشته باشند (محافظت CSRF).
  کلاینت‌های ماشینی می‌توانند هدر `x-api-token` برابر با `API_TOKEN` ارسال کنند.
- محدودیت نرخ روی ورود، OTP، بازیابی رمز، جستجو، لیست محصولات، QR، PDF، آپلود و فرم‌های عمومی.
- آدرس‌های خروجی (Webhook و تصاویر PDF) از نظر SSRF بررسی می‌شوند: شبکه‌ی داخلی،
  لوکال‌هاست و متادیتای ابری مسدود است، مگر با `ALLOW_PRIVATE_NETWORK=1`.
  با تنظیم `OUTBOUND_ALLOWED_HOSTS` می‌توان فقط چند هاست مشخص را مجاز کرد.
- قیمت‌های عمومی برای بازدیدکننده‌ی ناشناس به لایه‌های `PER_SQM` و `PER_SLAB` و `EXPORT`
  محدود می‌شوند؛ لایه‌های همکاری/پروژه فقط برای کاربران واردشده ارسال می‌شود.
- سفارش‌ها در سرور قیمت‌گذاری می‌شوند و عدد ارسالی کلاینت کاملاً نادیده گرفته می‌شود.
- هدرهای امنیتی (CSP، HSTS، X-Frame-Options، Referrer-Policy و ...) در `next.config.ts`
  تنظیم شده‌اند.

متغیرهای مهم:

| متغیر | توضیح |
| --- | --- |
| `TRUST_PROXY` | مقدار `0` یعنی به `X-Forwarded-For` اعتماد نشود (برای استقرار بدون پروکسی) |
| `API_TOKEN` | توکن کلاینت‌های ماشینی برای دور زدن بررسی CSRF |
| `OUTBOUND_ALLOWED_HOSTS` | فهرست هاست‌های مجاز برای درخواست‌های خروجی (با کاما جدا شود) |
| `ALLOW_PRIVATE_NETWORK` | مقدار `1` فقط برای توسعه؛ دسترسی به شبکه داخلی را مجاز می‌کند |
| `MAX_UPLOAD_MB` | سقف حجم آپلود تصویر |

نمونه‌ی کامل در `.env.example` آمده است.
